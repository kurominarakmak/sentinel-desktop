# Sentinel V3 OSS Source Audit

## Scope and method

This is a source-selection audit, not implementation. On 2026-08-06, each requested repository was shallow-cloned into `../sentinel-v3-oss` and inspected at the recorded `HEAD`. License text and relevant source modules—not only READMEs—were reviewed. No source, dependency, submodule, or production code was imported into Agent Sentinel.

Sentinel remains the only owner of task/workflow state, provider-session mapping, worktrees, permission decisions, validation, repair bounds, and completion. Provider adapters translate supported interfaces; the UI only renders state and requests user actions.

## Local OSS research directory

The V3 donor checkouts stay outside this repository and are read-only research
inputs. Resolve their location in this order:

```text
SENTINEL_V3_OSS_DIR environment variable
→ .sentinel/local.toml
→ ../sentinel-v3-oss fallback
```

Copy `.sentinel/local.example.toml` to `.sentinel/local.toml` only for a
machine-specific override; the local file is ignored and must not be committed.
Validate the checkout without modifying it with:

```sh
scripts/validate-oss-research-dir.sh
```

## Reuse-level policy

The original reuse labels (“direct dependency,” “port selected module,” “reference only,” and “reject”) describe distribution/integration method. This audit additionally applies the following decision level to every useful upstream surface:

| Level | Meaning | Required proof |
| --- | --- | --- |
| **A — Direct reuse** | Pure, permissively licensed module with limited coupling and a stable compatible interface. | Pin revision/version; provenance/notice entry; compatibility and security tests. |
| **B — Port with tests** | Useful algorithm, schema, or safety pattern in the wrong language/framework or coupled to the wrong host. | Locally reimplement only the isolated behavior in Rust/React; port/adapt upstream test cases before relying on it. |
| **C — Behavioral oracle** | Valuable interaction, state, recovery, or UX behavior whose code must not enter Sentinel. | State the observed contract and reproduce it with Sentinel-owned tests; do not copy source. |
| **Fallback reference** | Non-authoritative diagnostic or compatibility input, never allowed to change workflow state or authorization. | Label its provenance in UI/artifacts and test that its loss cannot change an authoritative decision. |

Every complete desktop application is **reject for whole-app reuse** regardless of any useful Level B/C module. The module-level catalog is in [V3 selected donors](v3-selected-donors.md).

## Cross-cutting conclusions

- No audited desktop application is eligible for wholesale reuse. Tauri/React alignment alone is insufficient when an upstream owns sessions, uses terminal scraping, or embeds a competing workflow. Reference-donor status preserves useful modules, concepts, and tests without importing those ownership models.
- Codex App Server integration should use its supported JSON-RPC interface, with `codex-plugin-cc` as an official type/reference aid. Jean and OpenCovibe are comparison fixtures only, not code donors.
- Claude Code must be integrated by a locally authored adapter over supported CLI/session interfaces. OpenCovibe/Jean/dmux/agent-sessions prove transcript and shell patterns exist, but none authorizes copying Claude implementation or delegates policy to Claude settings.
- ACP may be an optional future adapter boundary. Its schema can inform event evolution, but it is not the V3 internal event model and its inspected v2 module is unstable.
- V3 worktree cleanup should retain Sentinel's existing Rust `sentinel-git` authority. Cctop contributes only a narrow refresh-before-destruction refusal pattern.
- V3's review loop may use a locally reimplemented, versioned finding artifact informed by ralph-review and architect-loop; deterministic validation and the Sentinel state machine decide whether a task can be ready for human approval.

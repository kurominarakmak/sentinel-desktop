# Phase 2C2 React UI

The desktop prompt uses the typed Phase 2 commands only: submit, list/get runs, list events, cancellation, and runtime environment. `phase2-run-event` is best effort; SQLite event history is loaded on selection and reconciled by run ID and sequence number. The task form exposes only deterministic fake-agent scenarios. Codex is not enabled and Claude remains deferred.

The React listener is registered once and cleaned up on unmount. Persisted events are sorted and deduplicated with live events. A terminal live event refreshes the selected run and history. Rust's deprecated Phase 0 handlers remain temporarily for compatibility but have no React callers.

Persisted snapshots are merged functionally with current live events, never assigned over them. Merge is scoped by Run ID and sequence number; SQLite wins an identical-sequence conflict. Explicit selection is separate from background refresh: only user history selection and successful submission change `selectedId`. Terminal and cancellation refreshes are non-selecting, so history may update while another run remains selected. Selected detail and events are changed only when the current Run ID still matches.

Recent-run snapshots use a session-local monotonic request generation: only the newest `listRuns` request can replace the complete history, and stale responses or failures are discarded. A successful submission invalidates older requests and inserts its returned RunDto at the front of local newest-first history before selected-run recovery and best-effort synchronization begin. A post-submit history refresh failure is scoped, retryable, and cannot convert an already-created run into a failed submission.

The TypeScript `RunDto` mirrors the explicit desktop bridge DTO exactly for submit/get/list results. Event presentation is independent of event identity and recovery: sequence numbers, ordering, deduplication, and persisted/live precedence remain unchanged. The UI summarizes only allowlisted event types and fields; lifecycle events use fixed labels, documented message text is bounded and sanitized, and command/file/session/internal/unknown events use fixed or narrowly structured summaries. Display normalization and security inspection are separate: display text replaces unsafe controls with spaces, while inspection removes C0/C1 and invisible Unicode format characters before case-insensitive, separator-normalized path classification. Sensitive classification happens before visible truncation; Windows drive/UNC paths, bare drive roots, bare sensitive Unix/macOS roots, and separator-adjacent obfuscation are suppressed. Standalone SQL/admin commands and SQLite/database-engine diagnostics are also suppressed. Arbitrary JSON, paths, diagnostics, stacks, stderr, and secret-like values are redacted or omitted; malformed payloads receive a safe bounded fallback, while ordinary allowlisted agent text remains visible.

React consumes `cancellable` as a runtime capability snapshot. Cancellation operations are session-local and keyed by their initiating RunId with a per-run request identity: pending state and feedback render only when that same run is selected. Selecting another run neither transfers an old run's pending state or feedback nor disables an independently cancellable selected run. The initiating run still receives a non-selecting authoritative background refresh, and stale same-run continuations cannot replace a newer cancellation operation. React still refreshes and presents the authoritative cancellation result when ownership changes after a previously returned DTO, including `run_not_active`.

Lifecycle events `run_preparing`, `run_running`, `run_cancelling`, `run_cancelled`, `run_completed`, and `run_failed` refresh authoritative RunDto metadata. Per-run sequence and metadata-generation guards prevent an older response from regressing newer state. Repeated lifecycle or terminal sequences refresh once; terminal events use one final persisted-event and metadata refresh path. Non-lifecycle events do not fetch metadata, and lifecycle events for unselected runs only patch their history row without selecting them.

Persisted event recovery is best effort: an event-history failure retains current live events and cannot block the authoritative RunDto refresh. Explicit selection keeps its history DTO visible while recovering and reports event-history and metadata failures separately with a guarded Retry action; failures are caught and never render raw backend details. `cancellable` comes from current runtime ownership in the bridge, so persisted nonterminal runs after restart are visible but not cancellable. A `run_not_active` cancellation response refreshes the DTO and safely disables further cancellation; startup orphan reconciliation remains future work.

D2 integration coverage exercises the real prompt across persisted-before-live and live-before-persisted replay, persisted identical-sequence conflict precedence, stale persisted snapshots, out-of-order delivery, and cross-run isolation. It covers A→B→C selection races, missed-live terminal recovery, terminal/live/persisted deduplication, listener registration overlapping replay or rejecting, history Retry while selected recovery remains pending, and final unmount while listener registration and replay are unresolved. These cases preserve RunId/sequence ordering and keep background refreshes non-selecting.

D3 completes the production-facing frontend matrix. Submission accepts only the typed task text and allowlisted fake scenario, prevents duplicate requests while pending, clears the task after an accepted submission, and keeps post-success history/event/metadata failures scoped rather than relabeling a created run as failed. Cancellation displays the authoritative requested, already-cancelling, already-terminal, run-not-active, and termination-failed outcomes, then refreshes the RunDto without inventing a terminal state. Runtime availability uses the stable `{ schema_version, database_initialized, fake_agent_available }` DTO; it has scoped safe failure feedback and Retry, keeps persisted history browsable while unavailable, and invalidates late environment requests on unmount. Submission, cancellation, availability, history, and selected-recovery errors remain independently scoped.

Focus, render-boundary, bootstrap, and the consolidated R2a/R2b/R2c selection/lifecycle correctness batch are covered by focused frontend tests; the broader race and submission/cancellation validation suites remain separate.
